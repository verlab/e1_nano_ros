# 2. ROS 2 + RViz

```bash
ros2 launch e1_bringup sim.launch.py num:=4 rviz:=true
```

Esse launch sobe:

1. `rmw_zenohd`, o roteador Zenoh do ROS 2 (`start_router:=false` se você já tiver um);
2. `e1-sim` com 4 drones conectados ao roteador;
3. `e1_bridge`, o driver;
4. `e1_swarm_controller`, o controle de posição;
5. um `robot_state_publisher` por drone (`frame_prefix: e1_<id>/`) e o RViz com um RobotModel por drone.

!!! tip "RMW"
    Todos os terminais precisam de `export RMW_IMPLEMENTATION=rmw_zenoh_cpp`.

## Explorando

```bash
ros2 topic list | grep e1_1
ros2 topic echo /e1_1/state --once
ros2 topic hz /e1_1/pose                       # ~100 Hz
ros2 service call /e1/takeoff_all e1_msgs/srv/Takeoff "{height: 0.5, duration: 3.0}"
ros2 service call /e1_2/goto e1_msgs/srv/GoTo "{position: {x: 0.5, y: 0.0, z: 0.6}, yaw: 0.0, duration: 2.0}"
ros2 service call /e1/land_all e1_msgs/srv/Land "{duration: 3.0}"
ros2 service call /e1/emergency_stop std_srvs/srv/Trigger
```

## Missões de exemplo

```bash
ros2 launch e1_bringup sim.launch.py num:=1 mission:=square
ros2 launch e1_bringup sim.launch.py num:=6 layout:=circle mission:=formation
# ou isoladamente:
ros2 run e1_control square_mission --ros-args -p id:=1 -p side:=0.6 -p height:=0.4
```

## Streaming de setpoints (seu planejador)

Publique `e1_msgs/PositionTarget` em `/e1_<id>/setpoint` a qualquer taxa. O controlador segura o último
valor recebido:

```bash
ros2 topic pub -r 20 /e1_1/setpoint e1_msgs/msg/PositionTarget "{position: {x: 0.2, y: 0.1, z: 0.5}}"
```

Para comandar a atitude diretamente (controlador próprio), publique `e1_msgs/AttitudeTarget` em
`/e1_<id>/cmd/attitude` a pelo menos 10 Hz. Sem comandos por 0,5 s, o firmware desce sozinho.

Referência completa: [API ROS 2](../ros-api.md).
