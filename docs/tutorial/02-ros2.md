# 2. ROS 2 + RViz

```bash
ros2 launch e1_bringup sim.launch.py num:=4 rviz:=true
```

This launch file starts:

1. `rmw_zenohd`, the ROS 2 Zenoh router (`start_router:=false` if you already run one);
2. `e1-sim` with 4 drones connected to the router;
3. `e1_bridge`, the driver;
4. `e1_swarm_controller`, the position controller;
5. one `robot_state_publisher` per drone (`frame_prefix: e1_<id>/`) and RViz with one RobotModel per drone.

!!! tip "RMW"
    Every terminal needs `export RMW_IMPLEMENTATION=rmw_zenoh_cpp`.

## Exploring

```bash
ros2 topic list | grep e1_1
ros2 topic echo /e1_1/state --once
ros2 topic hz /e1_1/pose                       # ~100 Hz
ros2 service call /e1/takeoff_all e1_msgs/srv/Takeoff "{height: 0.5, duration: 3.0}"
ros2 service call /e1_2/goto e1_msgs/srv/GoTo "{position: {x: 0.5, y: 0.0, z: 0.6}, yaw: 0.0, duration: 2.0}"
ros2 service call /e1/land_all e1_msgs/srv/Land "{duration: 3.0}"
ros2 service call /e1/emergency_stop std_srvs/srv/Trigger
```

## Streaming setpoints (your planner)

Publish `e1_msgs/PositionTarget` on `/e1_<id>/setpoint` at any rate. The controller holds the last
received value:

```bash
ros2 topic pub -r 20 /e1_1/setpoint e1_msgs/msg/PositionTarget "{position: {x: 0.2, y: 0.1, z: 0.5}}"
```

To command attitude directly (your own controller), publish `e1_msgs/AttitudeTarget` on
`/e1_<id>/cmd/attitude` at 10 Hz or more. Without commands for 0.5 s, the firmware descends on its own.

Full reference: [ROS 2 API](../ros-api.md).
